### 为什么不能写“排序由估计噪声主导”

1. 两次IL+在线MC训练产生不同策略、经验、探索续策和标签目标，不能未经核验视作同一固定V^pi的重复无偏估计。
2. 中心化只消除状态内加性偏移，不消除目标策略差异、缩放、状态依赖偏差或训练访问分布差异。
3. 两个确定性函数的差不能单独分解为真实目标差、偏差和估计噪声。此次没有同固定策略/同标签目标的重复拟合对照。
4. 分歧大于间距也不逻辑推出给定动作对一定翻转。check-preflight.py保留了“候选整体分歧很大但该动作对同向”的数值反例。本次57.68%来自直接计算，不是从比值推断。
5. 跨Seed不一致不能证明同一Seed内的训练时间轴分类全是噪声。停止它基于当前资源门槛与预期收益，不是把尚未隔离的原因写成已确认根因。

## 3. 分辨增益：已经执行，不能取代符号检查

原始反事实分支来自ttc5-causal-20261011/work的两KDA模型cell4/5日志，未新跑任何环境。剔除涉及index0的动作对，其他原预定替代动作全部保留，不事后挑最有利动作。

主要实测对照为实际根后完整G差；另在两分支均成功、剩余步数不同的动作对上计算：

gain_duration = .99[V(a1)−V(a0)] / [.99^(L1−1)−.99^(L0−1)]

L从root实际执行动作到终止计数，包含root动作；不能用含共同前缀的全episode步数。实际root_return按root起点的每步Reward重新求和核对至1e−12。成功终止奖励为1，其余Reward对G差的贡献单独记录。

这些是按失败/保护root采样的实现回报动作对，不是自然全部候选分布；两分支成功条件也带选择偏差。没有将动作对当独立训练重复或给出总体根因比例。

本数据支持：在这些动作对上，网络间距相对实现终止回报差通常较小，并且大量方向相反。**幅度偏小与符号错误并不互斥。** 不能由有符号增益中位接近零就认定纯压缩，也不能用单世界G证明条件期望Q错误。

“普通安全候选即时r=0”不等于整个续跑Reward恒为零：未来可能有discomfort、碰撞和timeout。到达/终止候选也不是普通r=0情形。因此一般不能写V=gamma^剩余步数。即便两个root后继很近，恢复策略后可能分叉并改变终局；长期到达步数差没有≤1的保证。
